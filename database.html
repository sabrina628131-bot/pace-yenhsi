資料表與關係

資料表主要欄位關係與規則
classes 班級id、owner_id、title、join_code、capacity、created_at教師擁有班級，隨機 12 碼加入碼，最多 60 人。
members 成員id、class_id、user_id、alias、status、joined_at班級＋使用者唯一；班級＋代號唯一；待審核也占名額。
lessons 課程id、class_id、title、target_minutes、created_at、closed_at一班可有多堂課，可截止繳交。
activities 繳交id、class_id、lesson_id、member_id、user_id、client_id、started_at、seconds、meters、kcal、met、height、weight、age、point_count、created_at每人每堂課最多一筆；同一個本機紀錄不能重複繳交到其他課程。

classes → members / lessons → activities；刪除班級時會連帶刪除所有成員、課程與繳交紀錄。移除成員也會刪除該成員於此班的紀錄。伺服器以外鍵約束維持一致性，建立班級與首堂課使用資料庫批次交易。

教師看到什麼？

  • 班級碼、名額使用量、待審核學生；可核准或拒絕。
  • 每堂課已核准人數、已繳交人數、已繳交學生平均距離及平均運動時間。
  • 逐生的課堂代號、繳交狀態、距離、時間與總熱量。
  • CSV 另包含開始時間、MET、身高、體重、年齡、有效定位點數及繳交時間。

未繳交不自動判定缺席；熱量不作排名。本系統沒有背景即時追蹤、反作弊或自動評分功能。

權限設計

角色可做不可做
未登入查看介面、使用本機運動模板讀寫班級資料庫
學生申請加入、查看自己班級課程、確認繳交、查看與刪除自己的雲端紀錄讀取其他學生資料、審核成員、建立班級

教師資格由伺服器環境設定 TEACHER_EMAILS 控制，不提供前端「切換教師」按鈕。身份以平台簽入提供的穩定 user_id 綁定，每次 API 都驗證身份與班級歸屬。寫入要求同源 Origin 與 JSON；所有私人 API 回應使用 no-store，service worker 不快取 API。

容量與寫入策略

以一班 60 人、每週一堂、18 週計算，約 1,080 筆摘要；十個班約 10,800 筆。這是資料量規劃，非已完成的長期效能壓測。已驗證隔離測試中 61 次同時加入僅接受 60 人，及 60 人同時提交摘要成功。

運動結束後一次提交摘要，不連續將每秒 GPS 點寫入。上傳失敗時本機紀錄保留，可手動再繳交；使用唯一鍵避免重複請求新增多筆。沒有背景自動重試，不顯示未確認的「已同步」。

資料品質

伺服器拒收示範與未結束紀錄，限制秒數、距離、身高、體重、年齡及活動種類的範圍；檢查課程時間與速度合理性。熱量由伺服器以固定 MET 公式重新計算，不採信用戶端傳來的 kcal。這些驗證只能排除格式錯誤，無法證明學生真的完成運動。

隱私、保存與備份

學生每次勾選同意後才提交身體指標與摘要，不上傳完整經緯度或移動軌跡。建議以課堂代號取代姓名，老師於上課前說明用途、保存期限及替代活動。教師自行保管 CSV，避免放在公開分享資料夾。

目前提供手動 CSV 匯出及刪除；沒有自動到期刪除、排程備份或從 CSV 還原功能。建議每堂課匯出備份、學期結束依事先告知的期限刪除資料。雲端刪除不會清除學生裝置上的副本，本機刪除也不會撤回雲端繳交；兩邊各自管理。

正式上課前

  1. 目前網站仍保留擁有者私人存取；需在 Sites 分享設定中開放指定學生，不能把私人預覽網址當成全班已可存取。
  2. 目前登入採 ChatGPT 帳號。若學校政策要求 Google／校務帳號或獨立登入碼，需另接身分驗證並驗證角色對應。
  3. 老師建立實際班級、將加入碼提供給學生、逐一審核，避免將碼公開散佈。
  4. 以學生帳號完成一次登入、加入、核准、GPS 記錄、繳交及查看流程；Android／iPhone 各實測一次。
